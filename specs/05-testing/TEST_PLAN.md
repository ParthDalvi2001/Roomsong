# Test Plan & Test Cases — Roomsong

**Status:** Living · **Owner:** qa-engineer · **Version:** 1.2 (2026-10-10, plan v2.1 propagated by T-113: `08-status/PLAN_AMENDMENT_2026-10-10.md` §6, contract API_SPEC v1.2.1, D-019–D-030, and the code merged so far)
Levels: **Unit** (Vitest, agents run) · **Integration** (Vitest with fake audio context/XR stubs) · **E2E** (Playwright + IWER emulation, agents run) · **Device** (human on Quest, scripted by qa-engineer; **requires headset — none on the team as of 2026-10-10**, see REPLAN §1/§6) · **Perf** (emulator counters now; device fps once a headset exists).
Every test case maps to an SRS ID. Run `npm run verify` on every commit; `npm run test:e2e` before every merge to `develop`; CI runs both on every push and pull request to `develop` and `main` (`.github/workflows/ci.yml`; its first run on GitHub is still to come); device scripts per phase gate (G1..G3) and before release — as soon as a headset is in hand.
Geometry under test (REPLAN §3, D-020): annulus bed R_in 0.12 m / R_out 0.30 m, **5 rings × 16 steps = 80 cells**, bed centre **0.45 m** forward by default (range 0.35–0.45 m; *0.40 m: replaced, D-020*), reach cap 0.75 m. Provisional until TC-DEV-00: R_out 0.25 m if the outer ring fails, 12 steps if the inner ring fails (LLD §5.1).
Ids are never renumbered; a replaced number stays visible with its decision id. Each number is cited from the SRS; the design behind it is in LLD and API_SPEC, by section. A row marked **Built** has code and passes in the emulator today; every other row is the specification for the task that builds it.

---

## 1. Strategy
- Domain logic is pure → unit test exhaustively (fast, deterministic).
- Interaction = state machine → unit test transitions with synthetic `HandFrame` sequences, built inside the unit suites (the emulator has no per-joint input, §5).
- Rendering/audio integration → smoke tests in e2e (no crash, counters within budget, events emitted).
- Room fallbacks → e2e with `?flags=forceLevel=N`, plus device tests in ≥6 real rooms (once a headset exists).
- Room signature → pure function; unit test determinism/quantisation with fixture rooms; e2e checks the tuning ripple event timing.
- Perf → `perf:sample` assertions in e2e (draw calls, tris, voices, `maxFlashPerS`) + device fps via perf HUD / OVR Metrics (device only).
- Regression → the full suite on every PR; a tagged "golden" e2e run archived before release.
- Policy → gates inside `npm run verify` (no network API in `src/`, a sweep of the built bundle, the download budget) + the built pages under their Content Security Policy in e2e (built, T-109).

### 1.1 Emulator-first: what the emulator can and cannot verify
No Quest headset is on the team as of 2026-10-10 (T-000 = acquire one; H1 = Oct 20, Emergency mode if none by Oct 27). Until then every result is emulator-only and is reported as such. What the emulator supports was measured (IWER 2.5.0, 2026-10-10) and is asserted on every run by `tests/e2e/00-emulator.spec.ts` (E0); the full table is in `tests/e2e/README.md`.
| Emulator (IWER + Playwright; rooms and hand paths loaded by `tests/e2e/support/iwer.ts`) **can** verify | Emulator **cannot** verify (needs a headset + human report) |
|---|---|
| Pure logic: snap/annulus geometry, scale quantisation, scheduler timing (fake clock), signature determinism | Real frame rate (≥72 typical / ≥60 floor), JS ms on the Quest CPU, thermal throttling, the effect of FFR and MSAA (NFR-PERF-09) |
| Flows: placement chain via `forceLevel=1..4`, seed → plant → tide, Listen enter/exit, save/restore, onboarding timing with emulated input | Hand-tracking feel: pinch thresholds on real joints, the filter's beta (FR-HND-03), jitter, tracking loss as real hands produce it, first-try success rates |
| Draw/tri/voice budgets via `perf:sample`; heap soak via CDP | Real room detection quality: plane/semantic-label availability, anchor persistence, hit-test accuracy, untested rooms |
| Events emitted and ordered (`room:bedPlaced`, `room:tuned`, `listen:enter`, …) | Spatial audio localisation, audio clicks under device load, Quest Browser version quirks |
| What IWER 2.5.0 provides (E0, measured): an `immersive-ar` session with hand-tracking, plane-detection, mesh-detection, hit-test and anchors granted; planes and meshes with semantic labels (there is **no `desk` label**); hit-test; anchors and persistent handles; 25 joints per hand; a pinch (thumb–index gap 94 mm open, 2 mm closed) with `select` events | **Where IWER differs or shows nothing, so only a device check decides** (`tests/e2e/README.md`, E0): the order of `select` / `selectstart` / `selectend` (IWER sends `select` at pinch start) and whether Quest Browser delivers `select*` for hands at all (FR-HND-02); which way a plane's normal points (IWER's +Y points away from the room); `plane.orientation` (IWER takes it from the label) and `lastChangedTime` (changes every frame); joint jitter and the loss of single joints (IWER hands never jitter; only a whole hand can be lost: FR-HND-15); a failed anchor restore (handles always restore; a test must store an unknown handle); a declined room permission |
| Network and policy: zero requests off localhost from page load on, HTTP(S) and WebSocket (TC-E2E-01); the built pages under their Content Security Policy with zero violations (`04-built-page-policy.spec.ts`) | Load-to-session time: on software rendering it measures the host (2.6–5.3 s seen, BUG-003), so the emulator limit is 10 s and the 5 s product limit (FR-SYS-01/06) is TC-DEV-01. Pinch motion: the emulated hand closes in one frame and its pinch point jumps 7.7 cm, which the default filter (beta 0) cannot follow, so the pinch-page e2e runs with `?beta=100` |
| Audio logic with a fake context and offline renders: scheduling, stealing, peak level, pan side, graph shape (TC-AUD-*, TC-PERF-09) | Audio latency, polyphony before glitches, bass audibility on the headset speakers, the HRTF A/B (T-129, W1) |
Rule: a TC that passes only in the emulator is marked **E** in PROGRESS §Test status, never **D**. "Verified" without a human device report is not allowed. A pass that depends on an emulator trait in the right-hand column is no evidence for the device.

### 4.3 Unit — hands/
| ID | Covers | Case |

| TC-HND-01 | FR-HND-02 | Pinch, **two signals** (LLD §4, D-028). **Joint distance (the hold signal):** starts below 2.0 cm, ends above 3.2 cm, and a gap of 2.5 cm keeps whichever state it is in (hysteresis); each edge needs 2 consecutive samples, so a one-sample dip or gap changes nothing (debounce); no new pinch inside 130 ms of a release (lockout, fake clock). **Platform select (the tap signal):** `select` is true from `selectstart` to `selectend`; the lockout applies to it, hysteresis and debounce do not. **Rule:** a pinch that starts on a seed, the Listen orb, the undo petal, a panel control or nothing starts and ends on `select`; a pinch that starts on a plant starts and ends on `pinch`; the two are never OR-ed (a `select` edge alone does not grab a plant; a joint-distance edge alone does not press the orb); a source with no platform classifier reports `select = pinch`.
