## 3. Code checks (skill §3)

- [x] InstancedMesh for repeated geometry; per-instance colour attribute on the vine, the seeds, the petals
- [x] Geometries and materials reused, made in constructors; `dispose()` on every renderer (VineRenderer.dispose frees mesh, geometry, material)
- [x] Dirty flags: the vine writes `count`, `visible` and `opacity` only on change and its instance colours on `garden:changed`; the petal's colours attribute is flagged only when a petal is asked
- [x] No `new`, array literal, closure, spread, map or filter in an `update()` or the scheduler tick in the new code (heap tests for the vine and the petals; the halo, layers and stillness paths by inspection, see the gaps)
- [x] Overdraw: the vine is 48 small tubes (8 mm radius) with `depthWrite` off; no new large transparent plane (the Listen dome is pre-existing and Listen-only)
- [x] Audio: nodes built once (`dim` gain in the Layers constructor); `setTargetAtTime` for the sweep, the dim and the stillness send; pooled voices for the UI notes
- [x] Particles: unchanged (the undo burst pool; none under reduced motion)

**PASS pending device fps**, with no measured failure. Unmeasured, and what measures each:

2. **JS ms a frame**: the same run prints `… ms script` for the worst sample and the Listen sample (26-worst-frame.spec.ts l.255); record the two numbers in PROGRESS against the 6 ms budget.
3. **The 5-min heap soak after the merges**: `npm run test:e2e:heap` (TC-E2E-10) on `develop`; the last figure (+1.03 %, 6.0 kB a frame) predates vines, stillness, the time-lapse and the UI sounds.
